# 月次模擬試験とランキング 設計仕様

作成日: 2026-10-16。状態: 対話で合意した仕様と内部設計をまとめた、実装計画作成前のレビュー対象。本文の作成・コミットは、実装開始、本番DB変更、Cron有効化、pushの承認を意味しない。

## 1. 目的と実装範囲

学生が毎月共通の模擬試験で学習成果を確認し、試験別の順位を競えるようにする。教師は共有アカウント「管理者」で受験状況と結果を確認する。問題数・制限時間は本試験に合わせるが、採点は各問同配点の100点換算とし、IPAのIRT評価点や本試験の合否を再現するものとは表示しない。

対象は、月次の自動出題・公開、学生の受験・保存・再開・採点・履歴、教師の状況確認、暫定／確定ランキング、受験／順位報酬、未受験通知、ランキング称号7種類の有効化、既存称号への回答実績連携である。既存のログイン、教師名・権限、掲示板、画像アップロード、称号の購入・装備方式は変えない。

科目B、試験監督・外部資料閲覧の防止、教師による手動作問・点数訂正・再受験回数追加、メール通知、クラス別ランキングは対象外とする。公開過去問の正解を外部から探す行為まで防止できる試験ではない。

## 2. 対話で確定したルール

### 試験と開催期間

| 項目 | ITパスポート | 基本情報技術者 科目A |
| --- | --- | --- |
| 試験コード | it_passport | fe |
| 問題数 | 100問 | 60問 |
| 制限時間 | 120分 | 90分 |
| 月内の受験回数 | 最大2回 | 最大2回 |
| 受験報酬 | 初回提出時に20pt | 初回提出時に20pt |
| ランキング | 独立して集計 | 独立して集計 |

- 同じ学生が同じ月に両方の試験を受験できる。各試験の受験回数と報酬は独立する。
- すべての開催日時、月、通知予定日は日本時間 `Asia/Tokyo` とする。
- 毎月1日0時に自動公開する。受験期間は1日0時以上、25日0時未満であり、25日は受験期間に含めない。
- 25日0時以降は新規開始・回答変更を受け付けず、25日から月末までは確定ランキングを表示する。過去月も閲覧できる。
- 教師の公開確認は不要。登録済みの全年度の過去問から月ごとにランダム抽出する。
- 同じ試験・月では全学生に同一の問題セットと順序を提示し、2回目も同じセット・順序を使う。翌月は再抽選し、過去月との問題重複は許可する。

### 受験と結果公開

- 問題間を自由に移動し、未回答を確認し、提出前は選択を変更・解除できる。回答は自動保存する。
- ページを閉じても再開できるが、時間は止めない。再読み込み・別タブ・端末変更で開始時刻や残り時間をリセットしない。
- 受験期限は「開始時刻＋制限時間」と「25日0時」の早い方とする。期限到達時は保存済み回答で自動提出し、未回答は不正解とする。
- 各問の重みは同じ。得点・正答率は、正解数を全出題数で割って100倍する。未回答も分母に含める。
- 表示は小数第3位を四捨五入して小数第2位までとし、末尾の0は省略できる。例: 60問中50問正解は83.33点。順位比較に表示丸めを使わない。
- 提出直後に得点・正答率・獲得ポイントを表示する。問題別の正誤・正解・解説は、本人の2回目終了後であっても25日0時まで公開しない。
- 締切後の解説が元データにない場合は「解説は未登録です」と表示する。AI解説の自動生成やGeminiへの依存は追加しない。

### ランキングと報酬

- 提出・自動提出された結果を随時反映する。受験中の仮の正解数や未提出の結果を順位に使わない。
- 学生ごとに、その試験・月の提出済み結果の最高点を採用する。1回目と2回目の同点では1回目を代表結果とし、順位や報酬は変えない。
- 学生間の同点は同順位とする。順位は「自分より高得点の学生数＋1」で求める。例: 1位・1位・3位。解答時間・提出の早さで順位を分けない。
- 同順位内の表示順は安定した識別子順とし、見た目の並びを別順位として扱わない。
- 受験期間中は暫定順位を表示し、25日0時の締切後に未採点の期限切れ受験を処理して順位を確定する。
- 確定した各試験の1位に150pt、2位に100pt、3位に75ptを付与する。同順位の学生には全員同額を付与し、欠番の順位には付与しない。
- 受験報酬は各試験・月の初回提出時に20pt、2回目は0pt。両試験の初回提出で合計40ptを受け取れる。順位報酬も試験ごとに受け取れる。
- ランキング称号の判定と順位報酬は確定後だけ行う。暫定1位になっただけではアンロック・順位報酬を発行しない。

### 未受験通知

- 毎月20日9時に、その月の両試験がともに未提出の学生へベル通知を1回送る。一方を提出済みなら対象外とする。
- 受験中で提出済み結果がない学生も対象。通知から当月の模擬試験一覧に移動できる。
- 同じ学生・月では1回だけとし、試験別に2通送らない。「すべて既読」は追加せず、既存の個別既読を使う。

### 称号への連携

- 模擬試験の提出済み回答を累計回答数・分野別正解数の称号条件に含める。2回目も別の実回答として数える。
- 回答の変更・通信再送・採点の再実行では増やさない。最終的に未回答の問題は累計回答数に数えない。
- 過去問練習の完走回数・連続満点・60問満点／0点など、過去問練習限定の条件には含めない。一問一答・ランダム限定条件も変えない。
- ランキング実績は試験別に集計し、いずれかの試験で条件を達成すれば共通の称号を購入可能にする。異なる試験の実績は合算しない。
- アンロックは永久、購入は0pt、装備は手動のまま。自動所有・自動装備にはしない。ユーザー・称号につき通知は1回だけとする。

| キー | 称号 | 確定順位による条件 |
| --- | --- | --- |
| v1-009 | チャンピオン | 同一試験で1位を1回 |
| v1-011 | ランキング猛者 | 同一試験で3位以内を5か月連続 |
| v1-040 | シルバーコレクター | 同一試験で2位を通算3回 |
| v1-041 | ブロンズコレクター | 同一試験で3位を通算3回 |
| v1-042 | 銀メダル | 同一試験で2位を1回 |
| v1-043 | 銅メダル | 同一試験で3位を1回 |
| v1-044 | ゴールドコレクター | 同一試験で1位を通算3回 |

同順位もその順位の実績とする。コレクターは連続不要で、同一試験・月につき1回。5か月連続は日本時間の連続する暦月であり、未受験月・試験未開催月・4位以下の月が挟まると途切れる。過去に達成した最大連続記録も認める。「過去問くん」の固定58種類にランキング7種類を追加しない。

## 3. 画面構成

既存の学生／教師シェル、細いサイドバー、青いアクセント、日本語の表示を継承する。教師に称号ショップやマイページを追加しない。

- 学生の `/mock-exam`: 当月の2種類の試験カード、受験状態、残り回数、問題数・制限時間・締切、開始／再開／結果への導線、過去の受験結果を表示する。
- 受験画面: 1問ずつの表示、前後移動、番号別の回答状況、残り時間、自動保存の状態、提出前の未回答確認を設ける。正解を強調する既存練習用の回答処理は流用しない。
- 結果画面: 1回目／2回目それぞれの結果、採用中の最高点、受験報酬を表示する。締切前は解答解説の公開日を示し、締切後に問題ごとの選択・正解・解説を確認できる。
- 学生の `/ranking`: 試験種別と対象月を切り替え、暫定／集計中／確定の状態、上位3位までの全学生、自分の順位を表示する。上位と自分が重複する場合は同じ順位として扱う。
- ランキングには利用可能な学生の名前・アイコン・装備中称号を表示し、既存の公開プロフィールへリンクする。同点により上位3位の人数が増えても切り捨てない。
- 教師の `/teacher/mock-exams`: 月・試験種別ごとの開催状況、対象学生数、未受験／受験中／提出済み、学生ごとの1回目・2回目・最高点とランキングを確認できる。問題編集・点数訂正は設けない。
- 教師の既存ナビゲーションに模擬試験管理の導線を追加する。学生向けURLや他人の受験IDを使って権限を迂回できないようにする。

ランキングの画面上の反映は、提出直後の再取得と、表示中タブでの15秒間隔の自動再取得で行う。非表示タブでは停止し、再表示時に再取得する。これは提出結果の随時反映であり、WebSocketの常時接続や受験中の解答配信は行わない。

## 4. データ構造

DBアクセスはPrisma経由とする。既存の模擬試験関係4テーブルと `monthly_rankings` を利用し、固定した選択肢と自動処理の記録を追加する。

| テーブル | 追加・変更する責務 |
| --- | --- |
| mock_exams | 試験・対象月、公開／締切、固定問題数、開催状態、順位確定状態・確定日時を保持する |
| mock_exam_questions | 問題文・画像参照・出典・解説・分野を出題時点で保存し、試験内の重複と順序重複を禁止する |
| mock_exam_choices 新規 | 出題問題専用の選択肢ID・ラベル・本文・順序・正解を保存する。元の選択肢IDは出典情報であり、受験時の選択先とは分離する |
| mock_attempts | 開始要求ID、受験番号1／2、開始・期限・実効提出時刻・採点処理時刻、回答数・正解数、100点換算得点、受験報酬、更新バージョンを保持する |
| mock_answers | 出題問題との対応、選択中の固定選択肢、回答時刻・保存バージョン・直近の保存要求IDを保持する。選択肢は未回答時にnull、正誤は未採点時にnullとする |
| monthly_rankings | 模擬試験ID・採用受験ID・最高点・同順位を保持し、試験別の確定結果と順位報酬の根拠にする |
| mock_exam_job_runs 新規 | 処理種別・対象月／試験を一意にし、処理状態、再試行、実行権の期限、進捗、安全なエラー概要を記録する |
| notifications | 模擬試験の未受験通知種別・対象月を追加し、学生・種別・月で重複を防ぐ |
| point_transactions | 受験報酬は学生＋模擬試験ID、順位報酬は学生＋確定ランキング行IDを根拠に既存の一意キーで重複を防ぐ |

- `mock_exams` の試験・月の一意性は維持する。受験番号は1または2に制限し、模擬試験・学生・受験番号を一意とする。学生が同じ試験で同時に2件進行中にならない制約も設ける。
- 固定選択肢への参照に切り替え、元の問題・選択肢を編集しても受験内容・採点基準が変わらないようにする。受験・出題問題・選択肢の所属整合を検証・制約で保護する。
- 換算得点は小数第2位までを保存できる型に変更する。元の正解数・全問題数も残し、順位計算は正解数を根拠とする。同じ試験・月では分母が共通である。
- `monthly_rankings` の月・学生だけの一意制約を試験別へ改め、月・順位の一意制約は非一意の検索索引へ変更する。同点を拒否する制約を残さない。
- 暫定順位は提出済み受験から計算する。確定用の保存結果と混同せず、順位称号は確定フラグのある新しい試験別結果だけを参照する。
- 提出処理で既存プロフィールの累計回答・正解数を一度だけ更新するが、過去問練習回数は増やさない。既存の過去問練習専用の集計を模擬試験の回数へ読み替えない。
- 新規テーブルもRLSを有効にし、ブラウザーから直接読み書きする許可は追加しない。必要なFK索引と試験別・期限別の検索索引を設ける。

## 5. 出題データと保存の境界

- 全年度とは、年度情報のある登録済み過去問を意味する。公開済み・削除されていない・当該試験種別・選択肢4つ・正解が1つの候補に限定する。年度不明の補助問題・サンプルは除外する。基本情報は登録済みの科目A公開問題と科目A修了認定問題を対象とする。
- 初期版では、候補全体から重複なしに無作為抽出する。年度ごと・分野ごとの問題数を固定する方式ではない。本試験に合わせる範囲は問題数・時間・科目Aの出題形式であり、IRTや分野別の厳密な構成再現ではない。
- 画像必須の問題は、ビルド時に確認した配信資産の一覧と照合する。サーバーから大量の画像HTTPリクエストを行ったり、Vercel実行時の書込み可能ファイル領域に依存したりしない。
- 問題文・選択肢・正解・解説・分野・出典・画像パスを固定保存する。画像ファイル自体の永続コピー用Storageは追加せず、出題済み画像のパスや内容を上書き・削除しない運用とする。
- 不正な正解データや画像欠落の問題は候補から除外する。有効候補が必要数に足りなければ、問題数を減らさず公開準備を失敗として記録する。選択後にも内容を検証し、途中までの出題セットを公開しない。
- 問題準備は一貫した読み取りとトランザクションで行い、同じ試験・月の並行作成でも1セットだけを確定する。一度準備成功したセットは、閲覧・再実行で再抽選しない。

## 6. 回答保存と提出の流れ

1. 認証済み・有効な学生か、開催期間内か、残り回数があるかを確認する。開始要求IDで同じ要求の再送を識別し、既に終了していても同じ受験を返す。別の開始要求でも進行中の受験があれば新しい回数を消費せず、その受験を再開する。期限切れなら先に採点し、2回目の開始は新しい操作として確認する。
2. サーバーが受験番号・開始時刻・期限を決める。クライアントが送った残り時間、学生ID、得点、正誤、回数は採用しない。
3. 保存要求は出題問題・固定選択肢・期待バージョン・要求IDを指定する。保存のたびに期限と受験状態をロック取得後に確認し、古いタブによる上書きを409で拒否する。直近の同一要求ID・同一内容の再送は現在の保存結果を返すが、後続の変更と競合する古い再送は409とする。再送で実績を増やさない。
4. 画面は保存中・保存済み・未保存を区別する。送信失敗や応答不明を成功表示せず、正規の保存内容を再取得する。提出前に保存待ちを解消し、他タブ変更があれば再確認を求める。
5. 提出は、回答と出題時点の正解からサーバーで採点する。受験の提出確定、回答／正解数、受験報酬、ポイント履歴、実績連携を同じトランザクションで整合させる。再送は確定済み結果を返す。
6. 自動提出でも同じ採点処理を使う。処理実行が遅れた場合も実効提出時刻は期限とし、期限後の回答を採用しない。採点処理時刻は別に記録する。
7. 結果・ランキングを再取得する。締切前の学生向けレスポンスには固定データ中の正解フラグ・問題別正誤・解説を含めない。画面で隠すだけにはしない。

時計はサーバー／DBを基準とし、期限判定はロック待ち後の時刻でも確認する。ちょうど期限の新規開始・回答変更は受け付けない。期限切れ受験への提出・再開要求は、保存済み回答での自動提出結果へ導く。提出要求にも受験全体の期待バージョンを使い、別タブによる変更後に未確認の内容を確定しない。ネットワーク障害・ページ離脱を理由に時間延長や回数復活は行わない。開始が確定した受験を提出・自動提出したら1回として数える。

受験中の実際の選択操作は、既存の回答日・利用日の記録へ反映する。Cronによる自動採点やバックグラウンドの再取得だけで「学生が利用した日」を増やさない。累計回答と分野別正解の称号集計には、提出済みかつ最終選択のある回答だけを使う。

## 7. 順位確定と再実行

- 締切直後は集計中を表示できる。未処理の期限切れ受験を採点し、各学生の最高点を選び、同順位を算出して試験別の確定結果を保存する。
- 確定後の順位は、名前・アイコン・装備変更や通知の再試行で計算し直さない。利用できなくなった学生のプロフィール導線は無効化し、保存済み順位を詰め直さない。
- 順位の確定と報酬配布の進捗を区別する。確定済みの順位に基づき学生単位の短いトランザクションで報酬・称号を反映し、全対象の処理を確認して月次処理を完了する。
- 確定後に報酬処理が途中失敗しても確定順位を変えず、未完の対象から再開する。既存ポイント履歴・アンロック・通知の一意制約を根拠に、再実行で増殖させない。
- ロック順を統一し、試験、対象学生の安定順、受験・プロフィールの順で取得する。外部HTTP呼出しや全学生分の重い履歴読込を長いDBトランザクション内に持ち込まない。
- ランキング称号は過去の確定結果からも再判定できる。日常のショップ再評価でも永久アンロックを回復でき、同じ通知は再発行しない。

## 8. Supabase Cronと無料枠での運用

採用方式はSupabase Cronから、署名で保護したアプリ内のジョブ入口を呼び出す構成とする。業務データの処理はNext.js側の共通サービスとPrismaを使い、DB内に別の採点・報酬ロジックを重複実装しない。

- 1分間隔の軽量な実行入口から、実行すべき処理だけを選ぶ。期限切れ受験の採点、問題準備、20日9時の通知、25日0時以降の順位確定・報酬の補完を、小分けで実行する。
- 翌月分は25日以降に事前準備し、保存した公開開始時刻に基づき1日0時に表示可能にする。公開時刻ぴったりのジョブ成功だけに依存しない。
- 初回導入が1日から24日なら当月分も準備する。25日以降なら翌月分を準備し、過去月の試験・受験・順位を捏造しない。
- 受験の保存・再開・提出、結果／順位取得時にも期限切れを確認する。Cronが遅れても受験時間は延長しない。処理件数の上限に達して未採点分が残る間は、完全な確定順位と表示しない。
- 通知の遅延復旧は当月の締切前に限る。送信時にも両試験未提出・有効な学生か確認し、20日9時より後に登録した学生へ遡って通知しない。25日以降は当月の未受験通知を新規発行しない。
- ジョブの実行権には有効期限を設ける。途中停止しても、期限後に別の実行が再取得できる。対象月・試験・処理種別の記録と、各業務テーブルの一意制約の両方で重複を防ぐ。
- 再試行は間隔を空け、API障害時に無制限連打しない。業務上の完了記録は保持し、詳細な実行ログは保持期間を設ける。今回追加するCronの実行履歴は7日、アプリの詳細エラー履歴は30日を上限に整理し、他のジョブのログは削除しない。
- 処理の遅延・障害・無料プロジェクトの自動停止は起こり得る。通知・集計完了時刻の秒単位の保証や、Cronを有効化すれば無料プロジェクトが停止しないという保証はしない。
- 毎分1回の呼出しは、28日で40,320回、30日で43,200回、31日で44,640回／月となる。再試行を含む呼出し回数・DB負荷・通信・ログ容量・呼出し先Vercelの使用量を検証して確認する。無料プランを自動で有料化したり、課金上限を解除したりしない。

### ジョブ認証と環境分離

- `pg_net` のキューにはリクエストのヘッダーが保存されるため、service_role、Supabase secret key、永続的なCron秘密キーをそのまま送らない。
- 専用の共有秘密をSupabase VaultとVercelのサーバー環境変数に分離保管する。リクエストには短時間だけ有効なHMAC署名、時刻、nonce、対象環境を含める。署名はパス・本文・対象プロジェクトにも結び付け、期限切れ・改ざん・別環境の要求を拒否する。
- DB側の署名生成処理は非公開スキーマに置き、固定した検索パスと最小権限で実行する。anon／authenticatedから秘密の読出しや署名生成を呼べる関数を公開しない。
- ログ・レスポンス・Gitに秘密値を出さない。CronのHTTP応答は処理件数・成否だけとし、学生情報や採点用の正解を返さない。
- テストと本番では秘密と接続先を分ける。テストサーバーは専用テスト環境ファイルと既存の接続先ガードを使う。SupabaseからローカルPCへ直接HTTP接続できるとは想定せず、ローカルでは同じ入口と処理をテストから呼び出す。
- 機能公開・新規受験開始・定期実行を運用で停止できるようにする。初回は停止状態で配置し、必要なマイグレーションと接続先検証後に段階的に有効化する。

## 9. 画面とAPIの境界

- 学生の一覧・開始・受験読取・回答保存・提出・結果・ランキングと、教師の一覧／受験状況読取を分離する。内部ジョブ入口は学生・教師の通常APIとは分ける。
- すべてのAPIでサーバー認証と有効状態、roleを検証する。他人の受験を閲覧・変更できず、教師は学生として開始・提出・報酬受取できない。
- 学生の変更要求は既存方式に合わせて同一Originを確認する。ジョブ入口は専用署名で認証し、単なる学生・教師ログインを実行権限にしない。
- 日時・対象月・試験コード・ID・バージョン・選択肢を検証し、400／403／404／409を区別する。内部例外・SQL・接続情報を学生に返さない。
- 受験・結果・順位・通知の応答を他ユーザーと共有キャッシュしない。期限前に取得したデータで期限後の保存を許可しない。
- 既存の問題表示・アイコン・公開プロフィール・通知UIは、表示専用の契約で再利用する。即時採点する練習APIや、プロフィールの任意URLを画像として表示する処理は持ち込まない。

## 10. 境界仕様として明示する事項

以下は合意したルールを実装時に一意に解釈するための補足であり、この仕様書のレビューに含める。

- 開始後に全問未回答で提出・自動提出した場合も、0点の提出済み受験となり、回数を消費する。受験報酬の初回20ptにも最低回答数条件を追加しない。累計回答数は0のままとする。
- 順位報酬に最低得点や最低参加人数は設定しない。提出者が1人だけなら1位、0点で同点なら全員同順位になり得る。同順位の報酬・称号も通常どおり判定する。
- 最初から未受験の学生には0点の受験結果を作らず、順位・受験報酬を付与しない。
- 問題数や開催期間を教師が月途中で変更する機能は追加しない。登録された問題・画像に不備がある場合は通常のデータ修正・運用判断で対応し、出題済み試験を自動で差し替えない。
- 確定後に学生が利用停止・退会しても、既に確定した順位を再配分しない。移行で過去の確定実績を別の試験へ推測で割り当てない。

## 11. 現状確認と移行方針

- 専用テストDBで検証し、バックアップ・適用手順・停止手順を整えてから、本番マイグレーション、環境変数設定、デプロイ、Cron有効化をそれぞれ確認して進める。pushは別途承認を得る。
